# Safety Policy

组织内所有角色的安全底线，优先级高于任何任务目标。

## 破坏性操作

以下操作**默认禁止**，除非用户明确要求并确认：

- 删除文件或目录（包括 `rm`、`Remove-Item`、清空目录）
- 覆盖用户已有的、非本次任务创建的文件
- `git push --force`、`git reset --hard`、改写已发布的历史
- 修改全局环境（全局安装、修改系统配置、改动 PATH）
- 删除数据库表、清空数据、执行不可回滚的迁移

即便用户已确认，也必须：先说明影响范围 → 再执行 → 报告实际结果。

## 生产与外部环境

- 部署到生产环境、发布包到公共仓库、调用付费 API 前必须获得用户确认。
- 发送到外部服务的内容视为公开发布，不可包含密钥或用户隐私数据。

## 敏感信息

- 禁止在代码、日志、文档、提交信息中硬编码密钥、密码、Token。
- 密钥一律走环境变量或密钥管理服务，代码中只留占位符与说明。
- 发现仓库中已有泄露的密钥：立即提醒用户轮换，不要在报告中复制完整密钥。

## 依赖安全

- 引入新依赖前检查：维护状态、许可证、已知漏洞（CVE）。
- 禁止从不可信来源下载并执行脚本。

## 命令执行

- 长时间运行的服务放后台执行，不阻塞流程。
- 需要交互确认的命令一律加非交互参数（如 `--yes`）。
- 执行任何命令前评估风险；有风险的命令要说明为什么需要执行。

## 失败处理

- 命令失败时如实报告输出，禁止掩盖或谎报成功。
- 连续失败时停止重试，分析根因，必要时向用户求助。
