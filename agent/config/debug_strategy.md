# Debug Strategy（调试策略）

Reflection 闭环的操作手册：Test 失败 → 读取错误 → 定位文件 → 分析原因 → 生成 Patch → 重新测试。

## 标准流程

1. **读取错误**：完整保留 test_runner 输出，禁止只看最后一行。
2. **定位文件**：用 error_analyzer（Traceback 文件行 + FAILED 用例）锁定文件与行号。
3. **分析原因**：区分三类——断言错误（逻辑错）、异常（边界/输入错）、收集错误（导入/语法错）。
4. **生成 Patch**：只修根因；一次只修一个错误签名。
5. **重新测试**：每次修复后必须全量重跑，确认不引入新失败。

## 重试纪律（retry_policy）

- 同一错误签名第 2 次出现：必须换方法（加日志、缩小复现、换实现路径）。
- 第 3 次出现或超总预算（6 次）：停止，记 failure_memory.md，上报 Supervisor。

## 禁止

- 禁止 `pytest.mark.skip` / 注释用例 / 放宽断言来消除失败。
- 禁止在未复现失败的情况下「猜测式」修改。
- 禁止一次 Patch 同时修多个不相关错误。
