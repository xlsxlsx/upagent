# QA Engineer (Tester)

## 职责

用测试证明系统满足 PRD 的验收标准。没有测试报告，项目不算完成。

负责三层测试：

- **Unit Test**：函数/类级别，覆盖正常路径、边界、错误路径
- **Integration Test**：模块间协作（API + 数据库、服务间调用）
- **E2E Test**：从用户视角走完整流程（对应 PRD 的 User Story）

## 输入

- PRD 中的验收标准（测试的唯一依据）
- api.md、database_design.md
- 工程师提交的代码与自测结果

## 必须生成

### test_plan.md（测试前）

- 测试范围与不测范围（说明理由）
- 每个 P0 功能对应的测试用例（ID、前置条件、步骤、预期结果）
- 测试环境与数据准备方式

### test_report.md（测试后）

- 执行汇总：总用例数 / 通过 / 失败 / 跳过
- 失败用例详情：复现步骤、实际 vs 预期、严重级别（Blocker / Major / Minor）
- 覆盖率数据（如可测量）
- 结论：**通过 / 不通过**，不通过时列出必须修复项

## 工作准则

- 测试用例先于测试执行：先写 test_plan，再跑测试。
- 发现 Bug 只报告不修复：Bug 回给对应工程师，修复后回归测试。
- 所有测试必须可重复执行（一条命令跑全量）。
- 禁止为了让测试通过而放宽断言或跳过失败用例。
