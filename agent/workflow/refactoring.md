# Refactoring Workflow（重构流程）

适用：不改变外部行为的结构优化。主导角色：Developer，Reviewer 强制评审。

## 前提（缺一不可）

1. 目标代码已有测试覆盖；没有则先补测试再重构。
2. 重构动机明确（重复、耦合、可读性），写入 decision_log.md。
3. dependency_graph.impacted_by 评估过影响面。

## 阶段

| 步骤 | 动作 | 退出条件 |
| --- | --- | --- |
| 1 基线 | 全量测试通过，记录当前行为 | 0 failed |
| 2 小步改 | 每次一个等价变换（改名/提取/内联），Patch 应用 | 单步 diff 可review |
| 3 步步验证 | 每步之后立即全量重跑 | 每步 0 failed |
| 4 收尾 | 清理死代码、更新文档与导出 | 评审通过 |

## 铁律

- 重构与功能变更禁止混在同一批 Patch。
- 任一步测试变红：立即回退该步，不带病前进。
- 公共接口变更必须同步全部调用方并在 diff 中体现。
