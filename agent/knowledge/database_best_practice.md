# Database Best Practice（数据库最佳实践）

数据库设计与访问的强制准则，database 子域任务必读。

## 建模

- 每张表有单列主键；业务唯一性用唯一索引表达，不用业务字段当主键。
- 外键关系显式声明；软删除（deleted_at）需要连同唯一索引一起设计。
- 金额用整数最小货币单位或 DECIMAL，禁止浮点。
- 时间一律存 UTC（TIMESTAMPTZ / 带时区语义），展示层再转本地时区。

## 访问

- 只用参数化查询；任何字符串拼接 SQL 都是审计 Critical（security_rule.md）。
- 应用账号最小权限：业务库不给 DDL/SUPER 权限。
- N+1 查询是默认嫌疑：列表页需检查关联加载策略。
- 事务边界在服务层显式声明；长事务（跨网络调用）禁止。

## 演进

- 表结构变更全部走迁移脚本（可重放、可回滚），禁止手改线上库。
- 迁移与代码同评审同发布；破坏性变更（删列/改类型）分两步走（先兼容后清理）。
- 索引跟着查询走：先有慢查询证据再加索引，写多读少的表克制加索引。

## 检查清单

- [ ] 所有查询参数化
- [ ] 主键/唯一约束/外键齐全
- [ ] 金额与时间类型正确
- [ ] 有迁移脚本且可回滚
