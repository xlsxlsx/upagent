# Security Rules

开发期人人遵守的安全规则（防御性）。Security Auditor 在 security 阶段按此清单复查。

## 输入与注入

- 所有外部输入（请求参数、Header、Cookie、文件名、上传内容）都不可信，必须校验。
- SQL 一律参数化查询 / ORM，禁止字符串拼接 SQL。
- 执行系统命令禁止拼接用户输入；能用库函数就不调 shell。
- 文件路径操作必须规范化并校验在允许目录内（防路径穿越）。

## 认证

- 密码使用自适应哈希（bcrypt / argon2），禁止 MD5/SHA1/明文。
- 会话 Token 使用加密安全随机数；设置合理有效期与刷新机制。
- 登录接口做失败次数限制或延迟，防暴力破解。
- 登录失败提示统一措辞，不暴露「用户名不存在 / 密码错误」差别。

## 授权

- 每个需要权限的端点都在**服务端**校验，不依赖前端隐藏按钮。
- 按资源归属校验（防水平越权）：查询他人 ID 的数据必须做归属检查。
- 默认拒绝：未明确授权的操作一律拒绝。

## Web 防护

- 输出到 HTML 的用户内容一律转义或使用框架的安全渲染（防 XSS）。
- 状态变更接口启用 CSRF 防护；Cookie 设置 `HttpOnly` + `SameSite` + `Secure`。
- CORS 白名单明确来源，禁止生产环境 `*`。
- 生产环境关闭调试模式，错误响应不暴露堆栈与内部路径。

## 敏感数据

- 密钥/凭证只走环境变量或密钥服务，禁止入代码与版本库。
- 日志脱敏：不记录密码、完整 Token、身份证号、银行卡号。
- 传输一律 HTTPS；敏感字段存储加密或哈希。

## 依赖

- 引入前检查维护状态与已知 CVE；锁定版本。
- 定期（每次交付前）跑依赖漏洞扫描。

## 违规处理

开发中发现违反本规则的代码 → 按 Bug 处理，级别不低于 Major；
涉及认证/授权/注入的按 Blocker 处理。
