# API Design（API 设计知识）

对外接口（REST 为主）的设计准则，backend 子域任务必读。

## 资源与动词

- URL 表达资源（名词复数）：`/orders/{id}`；动作用 HTTP 方法表达。
- GET 幂等无副作用；写操作幂等性：PUT 天然幂等，POST 配合幂等键（Idempotency-Key）。
- 批量与子资源：`/orders/{id}/items`；避免 RPC 风格 `/getOrderById`。

## 请求与响应

- 统一响应结构：成功 `{data}`，失败 `{error: {code, message, details}}`。
- 错误码语义：400 参数错 / 401 未认证 / 403 无权限 / 404 不存在 / 409 冲突 / 422 业务校验失败。
- 分页强制：列表接口必须有 `limit`（有上限）+ 游标或页码；禁止无界查询。
- 字段命名一致（snake_case 或 camelCase 二选一），时间用 ISO-8601 UTC。

## 兼容与版本

- 破坏性变更必须升版本（/v2）或新字段旁路过渡；已发布字段不改语义。
- 新增字段必须可选、有默认值；客户端未知字段必须忽略。

## 安全底线

- 所有接口过认证中间件，白名单显式声明公开接口。
- 对象级权限：校验「当前用户是否有权操作该 id」，不是只校验登录。
- 入参全部服务端校验；敏感字段（密码、token）永不出现在响应与日志。
