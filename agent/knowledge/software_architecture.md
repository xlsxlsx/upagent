# Software Architecture（软件架构知识）

架构决策时的通用准则，Architect 角色设计前必读。

## 分层原则

- 依赖只指向内层：UI → 应用逻辑 → 领域 → 基础设施抽象。
- 核心逻辑不依赖框架/IO；外部能力（DB、HTTP、LLM）以接口注入。
- 一个模块只暴露必要接口，内部实现自由演化。

## 架构选型速查

| 场景 | 首选 | 理由 |
| --- | --- | --- |
| 中小型 Web 应用 | 单体 + 模块化分层 | 部署简单，边界靠包结构维持 |
| 明确的多团队/多伸缩域 | 服务拆分（按业务域） | 独立部署伸缩，成本是运维复杂度 |
| 事件驱动协作 | 消息/事件总线 | 解耦生产者消费者，注意幂等 |
| 读多写少 | 缓存 + 读写分离 | 先量化再引入，避免过早优化 |

## 关键取舍纪律

- 先单体后拆分：没有量化痛点不引入分布式。
- 任何架构决策必须记录：决策、理由、被否方案（decision_log.md）。
- 边界处定义契约（schema/接口），跨边界不共享可变状态。

## 演进检查

- 循环依赖 = 边界错误，立即修正（dependency_graph 可检测）。
- 一个改动经常要跨 3+ 模块 = 内聚不足，考虑重新划界。
